# BloodLink

BloodLink is a web application for managing blood supply across hospitals and blood banks: inventory, requests between facilities, a per-facility stock forecast, and donor outreach (simulated; no SMS provider is connected). It is an undergraduate computer science thesis project at the University of Batangas.

## Stack

- **Frontend:** React 18, TypeScript, Vite, Tailwind CSS 4, Recharts, Leaflet. Deployed on Vercel.
- **Backend:** FastAPI, SQLAlchemy (psycopg2), PostgreSQL (Supabase). Deployed on Render.
- **Forecasting:** SARIMAX (statsmodels) with a dengue-season regressor, fitted per facility and blood type.

## Run it locally

You need Node 24, Python 3.13 and PostgreSQL 17 or newer.

**Database.** Create an empty database, then load the schema. The dump creates the `public` schema itself, so drop the empty default one first (use a plain `postgresql://` URL for `psql`, without `+psycopg2`):

```
psql "<your database url>" -c "DROP SCHEMA public CASCADE"
psql "<your database url>" -f server/tests/schema.sql
```

`server/tests/schema.sql` is a schema-only dump of the production database; the test suite loads it the same way. Create the first admin account with `python seed_admin_user.py <email> <password>` from `server/` (see `server/.env.example`).

**Backend** (from `server/`):

```
python -m venv .venv
.venv\Scripts\activate          # Windows; on macOS/Linux: source .venv/bin/activate
pip install -r requirements-dev.txt
copy .env.example .env          # then fill in DATABASE_URL, JWT_SECRET and CORS_ALLOWED_ORIGINS
uvicorn main:app --reload --port 8000
```

`DATABASE_URL` must start with `postgresql+psycopg2://`. `CORS_ALLOWED_ORIGINS` must include the frontend origin (`http://localhost:5173`); the backend refuses all cross-origin requests while it is unset.

**Frontend** (from the repository root):

```
npm install
copy .env.example .env.local    # VITE_API_BASE_URL points at the backend, e.g. http://localhost:8000
npm run dev
```

## Run the tests

The backend suite needs a **scratch** local PostgreSQL database. It drops and rebuilds that database's `public` schema, and it refuses to run against a non-local host or without `TEST_DATABASE_URL`. From the repository root:

```
set TEST_DATABASE_URL=postgresql+psycopg2://<user>:<password>@localhost:5432/<scratch database>
server\.venv\Scripts\python.exe -m pytest server/tests -q
```

On macOS/Linux use `export TEST_DATABASE_URL=...` and `server/.venv/bin/python`. Never run the suite through `python -m unittest`: that skips the safeguard and uses `DATABASE_URL`.

The frontend checks:

```
npm run typecheck
node scripts/check_stock_bands.ts
node scripts/check_forecast_source_tags.ts
node scripts/check_trend_chart.ts
node scripts/check_incoming_groups.ts
node scripts/check_components.ts
node scripts/check_request_timeline.ts
node scripts/check_transfers.ts
node scripts/check_bank_dashboard.ts
node scripts/check_bank_inventory.ts
node scripts/check_notifications.ts
```

Each script prints `ok` when it passes.

## Where the documentation is

- `CLAUDE.md`: the engineering rules and conventions for working in this repository.
- `PRODUCT.md` and `DESIGN.md`: product context and the design system.
- `DEPLOYMENT.md`: deployment notes.
- `docs/DATA_DICTIONARY.md`: the database schema reference, generated by `docs/build_data_dictionary.py`.
- `docs/methodology/`: the forecasting methodology, generated from demonstration data.
- `server/DENGUE_INDEX_DERIVATION.md` and `server/SYNTHETIC_SARIMAX_VALIDATION.md`: records of the forecasting research.

The data under `docs/methodology/`, `demo/` and the synthetic-forecast scripts is generated demonstration data, not real blood bank records.
